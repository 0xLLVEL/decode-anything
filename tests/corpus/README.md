# End-to-end corpus

These files feed the **whole** `decompile_file` pipeline: signature detection,
engine decode, IR loading, AST reconstruction, post-processing, and `php -l`
validation. Each case has an encoded input (`hello.php`) and a committed
golden output (`hello.expected.php`).

| Case | Encoder | Input shape |
| --- | --- | --- |
| `yakpro/` | YAK Pro | Handwritten source-level obfuscation: dispatcher `goto`s, inverted guard, hex-escaped literals, YAK Pro header |
| `sourceguardian/hello.php` | SourceGuardian | Real `sg_load` container wrapping a PHP 8.1 `op_array` that echoes a string |
| `sourceguardian/class.php` | SourceGuardian | Same container format, carrying a final class with static/instance properties, typed + nullable + readonly declarations, defaults, and a default parameter |

## Provenance

- `yakpro/hello.php` is written for this repository. It is not output from the
  commercial YAK Pro tool; it reproduces the constructs the deobfuscator
  handles, so the test does not redistribute third-party protected code.
- `sourceguardian/hello.php` is generated by
  `python tools/build_corpus_fixtures.py`. The container is sealed with the
  first key in `engines/sourceguardian/keys.py` and carries a hand-built
  bytecode body, so the normal decode path runs without vendor code.

## Regenerating

```bash
python tools/build_corpus_fixtures.py --name hello
python tools/build_corpus_fixtures.py --name class
```

The builder is deterministic and accepts `-o/--output`. The regression suite
also regenerates each container into a temp directory and compares the text,
so a stale fixture fails the build.

## Why there is no ionCube case

An `HR+c` payload cannot be synthesized honestly here: its body is encrypted
with per-file material and its interned strings resolve through the matching
loader binary. A fake header would exercise the error path, not the decoder.
Real ionCube samples belong in a private corpus, not this repository.
